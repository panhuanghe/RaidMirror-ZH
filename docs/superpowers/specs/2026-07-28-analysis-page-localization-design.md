# 分析页中文化扫尾设计

## 目标

清理战斗分析整页仍对用户可见的英文与中英混排文案，并避免后续运行 `build_zh.py` 时恢复英文。

## 范围

- 汉化分析页标签、统计卡片、摘要卡片、空状态、提示、工具提示、复制摘要和动态建议。
- 保留通用术语 `DPS`、`HPS`、`WCL`、`Boss`。
- 将 `Pull`、`CD`、`Off CD` 分别显示为“尝试”“冷却”“爆发技能”。
- 副本、首领和技能名优先使用现有 ID/名称映射；没有可靠官方名称时保留原名，不猜译。
- 不改变布局、颜色、交互、统计逻辑、GraphQL 查询和内部数据键。

## 实现方案

同步修改最终页面 `index.html` 与生成器 `build_zh.py`。静态文案加入生成器替换表；动态模板在生成器后处理阶段同步覆盖，确保重新生成后的页面保持一致。只修改显示字符串，不翻译函数名、变量名、GraphQL 字段或枚举值。

## 重点文案

- 页签与摘要：`Off CDs`、`Timeline`、`Summary`、`Raid Lead Summary`。
- 指标：`Total Deaths`、`Potion Users`、`Healthstone Users`、`Avg DPS/HPS`、`Missed Off CDs`。
- 摘要卡：干部笔记、死亡上下文、就位确认、消耗品快照、机制观察、冷却覆盖、尝试趋势。
- 动态语句：死亡前伤害、治疗石/药水状态、Boss 技能窗口、坦克减伤建议、机制处理建议。
- 其他可见残留：空状态、说明文字、表头、按钮标题、复制文本。

## 验证

- 新增英文残留回归脚本，覆盖本次识别出的可见文案。
- 先运行测试确认当前页面失败，再完成翻译并确认通过。
- 运行 GraphQL 契约测试、JavaScript 语法检查和 ESLint `no-undef` 检查。
- 对关键摘要区做本地页面视觉检查，确认无布局溢出或异常换行。
- 更新 README、DEPLOY、CHANGELOG 至 `v1.0.15`，打包并验证 GitHub Release 资产。
